# PS1 v0.1 Implementation Plan

> **For agentic workers:** Use `superpowers:executing-plans` to implement this plan sequentially. Steps use checkbox syntax. This is a handoff to another agent, not an instruction to launch agents automatically. Apply Helena's current delegation rules if delegation is later requested.

**Goal:** Build a standalone PS1 executable with stable double-buffered video and a rotating, flat-colored unlit cube.

**Architecture:** A PSYQo `Application` adapter owns one cube `Scene`, which calls a narrow PS1 renderer. The renderer owns two persistent packet/table contexts; PSYQo owns presentation. A small tracked patch to the pinned SDK establishes drawing completion and fresh VBlank before display swaps.

**Tech Stack:** C++20, PSYQo/Nugget `625da805c4a9bfd56dd9b2b17409805c0591dd42`, MIPS I cross-compiler in a digest-pinned Docker image, GNU Make, PowerShell wrappers, PCSX-Redux with OpenBIOS.

**Spec:** [Approved PS1 v0.1 design](../specs/2026-09-15-ps1-v01-design.md). Read both supplied reference documents linked there before implementation.

## Global constraints

- Standalone native host first. Editor integration, generated runtime, and authored scene export follow in a separate milestone.
- 320 × 240 progressive NTSC baseline, 15-bit RGB in 16-bit framebuffer storage, double buffered.
- Six distinct, constant face colors: no normals, lights, textures, fog, or blending.
- A fixed perspective camera; no controller or external asset required.
- Backface rejection and far-to-near ordering. No software depth buffer.
- Native rendering settings during validation: no enhanced resolution, geometry correction, extra RAM, or CPU overclock.
- General near-plane clipping is deferred. Reject an invalid diagnostic pose with a specific failure; do not present this as arbitrary-scene rendering.
- No per-frame heap allocation. Two packet contexts, each with a 4 KiB packet budget and 256 ordering buckets.
- Use namespace `helengine::ps1`, one class per file, substantive member/ownership documentation.
- Engine sources stay under this repository. Build products, copied SDK sources, logs, and test output stay under `C:\dev\helworks\builds\helengine-ps1`.
- No shared repository changes, SDK swap, generated-runtime integration, custom assembly optimization, or additional platform subsystem.
- No screenshots of Helena's screen/windows without her explicit permission. Use logs, debugger data, and permitted emulator exports; request visual confirmation if needed.
- A missing emulator or physical console must be reported as a validation limitation. Never mark those checks passed from successful compilation.

```text
wait for the prior deferred chain's transfer/OTC completion, pumping callbacks
acknowledge any old GPU IRQ marker with GP1(02h)

pump callbacks until GPUSTAT bit 24 reports the ordered marker, or timeout
```

- [ ] **2.2 Add typed persistent packet storage.** Avoid a general raw byte allocator for one primitive family. Each frame context holds `OrderingTable<256>`, one clear fragment, a typed array of triangle fragments fitting the remainder of a 4,096-byte packet budget, reservation counters, and state. On target assert:

```cpp
using TriangleFragment = psyqo::Fragments::SimpleFragment<psyqo::Prim::Triangle>;
using ClearFragment = psyqo::Fragments::SimpleFragment<psyqo::Prim::FastFill>;
static_assert(sizeof(TriangleFragment) == 20);
static_assert(sizeof(psyqo::OrderingTable<256>) == 1028);
constexpr unsigned TriangleCapacity = (4096 - sizeof(ClearFragment)) / sizeof(TriangleFragment);
static_assert(TriangleCapacity >= 12);
```

Use actual `sizeof` rather than assuming a 64-bit host layout matches PS1 DMA. `Begin` transitions Available→Building and resets counters only after the prior matching parity context has been reclaimed; `Submit` transitions Building→Queued; reuse requires the scene callback after SDK completion/presentation for that context. Keep a monotonically increasing scene sequence and record last submission sequence; a parity context must not be reused on the immediately following callback. Assert wrong-state transitions. The SDK schedules table clearing after transfer; do not clear an in-flight table manually.

Define the target class boundary explicitly:

```cpp
class Ps1FrameContext {
public:
    using TriangleFragment = psyqo::Fragments::SimpleFragment<psyqo::Prim::Triangle>;
    bool Begin(uint32_t sceneSequence);
    TriangleFragment* TryReserveTriangle();
    bool Insert(TriangleFragment& fragment, uint16_t bucket);
    bool Submit(psyqo::GPU& gpu);
    void Cancel(); // Only an unsent Building context; clear its table and reset state.
    uint32_t UsedPackets() const;
    uint32_t HighWaterBytes() const;
};
```

`Begin` may reclaim Queued only when unsigned sequence distance from its previous submission is at least two and the caller has selected the matching SDK parity after the patched lifecycle. It never interprets parity alone as a completion event. `Submit` chains the context's clear and table once and stores its sequence; it does not directly invoke `flip` or `sendChain`. `Insert` requires Building, a fragment from this context's currently reserved range, and bucket below 256. The renderer owns both contexts and its scene sequence.

Queue complete work only after successful construction: `getNextClear`, `chain(clear)`, `chain(table)`. The fixed scene builds at most twelve triangle packets. Count submitted, backface-rejected, degenerate, invalid, and high-water packet use. If construction fails before submission, reset that unsent table while it is CPU-owned, then stop with a diagnostic; never present half a cube as success.
